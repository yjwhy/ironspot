## Phase 2 carryover gaps surfaced during Task 33 (not blockers)

Discovered while inspecting prod schema via Supabase MCP `list_tables`:

- **`users.deleted_at` missing in prod** — Phase 2 Task 30 (PR #45 cf5dcbd) added the column to `init-test-db.sql` and shipped `UserRepository.findById` / `markDeleted` referencing it, but the prod schema doesn't have it. Any `GET /api/users/me` call against prod currently fails at runtime because the JOOQ query has `WHERE deleted_at IS NULL`. Needs a one-line `ALTER TABLE users ADD COLUMN deleted_at TIMESTAMPTZ` on Supabase. Separate Task / hotfix.
- **`reports.reviewed_at` exists in prod but missing from `init-test-db.sql`** — purely a test-schema drift; tests won't observe it. Low priority alignment.
- **`reports.status` is a Postgres enum in prod, `TEXT` in test schema** — JOOQ generates `String` from the test schema; prod accepts string-cast values fine, no immediate impact, but test fixtures can't reproduce constraint violation tests for invalid status values.
- **`users.role` CHECK includes `'owner'` in prod but only `('user', 'admin')` in test schema** — test is stricter, no impact on Task 33 since we only insert `'user'`/`'admin'`. Likely Phase 4 (gym owner workflow) artefact.
- **`reports_unique_reporter_target` UNIQUE constraint exists in test schema but not surfaced by prod `list_tables`** — would need direct `pg_constraint` query to confirm. Task 27 plan asserts both should have it.
