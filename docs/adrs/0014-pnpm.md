# ADR 0014: 패키지 매니저는 pnpm

**Status:** Accepted · 2026-04-15

## Context

Expo 프로젝트의 패키지 매니저 선택. 후보: npm (기본), yarn, pnpm.

## Decision

**pnpm.**

## Alternatives

- **npm** — 설치 가장 느림. 의존성 중복 저장으로 디스크 용량 많이 사용.
- **yarn (classic)** — npm보다 낫지만 여전히 의존성 복사. Yarn Berry (v3+)는 기능 좋지만 React Native에서 PnP 호환 이슈.
- **bun** — 빠르지만 2026년 기준 Expo/RN 생태계 호환성이 일관되지 않음.

## Consequences

**긍정적:**

- 가장 빠른 설치 (복사 대신 심볼릭 링크)
- 가장 작은 디스크 사용 (공유 글로벌 저장소)
- 엄격한 의존성 해석으로 phantom dependency 방지
- 개발자의 현 직장에서도 사용 중 (도구 일관성)

**부정적:**

- 일부 덜 일반적인 도구가 npm 호환성 워크어라운드 필요
- 팀원이 익숙하지 않으면 학습 곡선 존재

## 참고사항

패키지 매니저 선택은 채용 가능성에 영향 없음. yarn 쓰는 한국 회사도 pnpm으로 개발된 프로젝트를 문제없이 수용 — 결과물 (`package.json` + lockfile)은 어디서든 통용됨.
